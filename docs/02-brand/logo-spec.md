# مشخصات فنی لوگو و آیکون

**برای:** طراح محصول (طراحی لوگو و پالت در Figma) · **مرحله:** ۲ از ۱۳ (هویت بصری)

این سند فقط الزامات فنی و محدودیت‌هایی رو جمع می‌کنه که از تصمیم‌های قبلی و پلتفرم‌ها میاد. مسیر خلاقانه کاملاً با طراحه.

> علامت ⚠️ یعنی موردی که از منبع رسمی تأیید نشد و قبل از خروجی نهایی باید در پنل مربوطه چک بشه.

---

## ۱. الزامات برند

از [پلتفرم برند](brand-platform.md) و دفتر تصمیم‌ها:

| الزام | منبع |
|---|---|
| سیستم لوگو: یک **نماد** بدون وابستگی به زبان، کنار **نوشتار فارسی** «دیدیت» و **نوشتار انگلیسی** «Didit» | D-016، D-028 |
| نماد باید بدون نوشتار، به‌عنوان آیکون اپ، قابل شناسایی باشه | D-016، D-028 |
| فونت برند: Estedad (برای نوشتارها می‌شه ازش شروع کرد یا لترینگ سفارشی ساخت) | D-017 |
| شخصیت: صادق و گرم | D-015 |
| پالت باید رنگ مشخص برای «بله» و «خیر» داشته باشه؛ «خیر» قرمز نباشه | پلتفرم برند |
| هر رنگ اصلی یک نسخه‌ی تم تیره داشته باشه | پلتفرم برند |

## ۲. خروجی‌های مورد نیاز

### لوگو

- [ ] نماد: رنگی، تک‌رنگ تیره، تک‌رنگ روشن (معکوس)
- [ ] لوگوی فارسی: نماد + «دیدیت»، افقی
- [ ] لوگوی انگلیسی: نماد + «Didit»، افقی
- [ ] (اختیاری) نسخه‌ی عمودی هر دو
- [ ] حاشیه‌ی امن (Clear space) و حداقل اندازه‌ی چاپ و نمایش
- [ ] فرمت: SVG برای همه؛ PNG فقط جایی که پلتفرم خواسته

### پالت

- [ ] رنگ اصلی برند
- [ ] رنگ متن (تیره) و پس‌زمینه (روشن)
- [ ] رنگ «بله» و رنگ «خیر»
- [ ] (اختیاری) رنگ تأکید برای «امروز» و لحظه‌های مهم مثل مدال
- [ ] نسخه‌ی تم تیره‌ی هر رنگ؛ اگه وقت نشد، من پیشنهادش رو می‌سازم و تو تأیید می‌کنی

**کنتراست (WCAG 2.1، سطح AA):** متن معمولی حداقل ۴٫۵ به ۱، متن بزرگ و آیکون حداقل ۳ به ۱. بعد از تحویل، همه‌ی جفت‌رنگ‌ها رو چک می‌کنم.

## ۳. آیکون اپ اندروید (Adaptive Icon)

منبع: [Android Developers — Adaptive icons](https://developer.android.com/develop/ui/views/launch/icon_design_adaptive)

| مورد | مقدار |
|---|---|
| اندازه‌ی هر لایه (پس‌زمینه، پیش‌زمینه، تک‌رنگ) | ۱۰۸×۱۰۸ dp |
| ناحیه‌ی امن نماد (هرگز توسط ماسک سازنده‌ی گوشی بریده نمی‌شه) | ۶۶×۶۶ dp در مرکز |
| اندازه‌ی نماد | حداقل ۴۸×۴۸ dp، حداکثر ۶۶×۶۶ dp |
| حاشیه‌ی رزرو برای ماسک و افکت | ۱۸ dp از هر طرف |
| آیکون تک‌رنگ (Themed icon، اندروید ۱۳ به بعد) | یک لایه‌ی جدا ۱۰۸×۱۰۸ dp؛ سیستم با رنگ‌های والپیپر رنگش می‌کنه |

**یعنی:** نماد باید طوری طراحی بشه که در دایره، مربع گرد و هر شکل دیگه‌ای که سازنده‌ی گوشی انتخاب کنه درست دیده بشه. یک نسخه‌ی تک‌رنگ هم لازمه.

### آیکون کوچک نوتیفیکیشن

- اندروید برای هر نوتیفیکیشن یک آیکون کوچک (`setSmallIcon`) لازم داره و این تنها محتوای اجباری نوتیفیکیشنه ([منبع](https://developer.android.com/develop/ui/views/notifications/build-notification)).
- ⚠️ طبق رفتار رایج اندروید، سیستم فقط کانال شفافیت (Alpha) این آیکون رو استفاده می‌کنه. پس باید یک **سیلوئت تک‌رنگ ساده روی زمینه‌ی شفاف** باشه، حدود ۲۴×۲۴ dp. جزئیات ریز در این اندازه از بین می‌ره. (در صفحه‌های رسمی‌ای که بررسی شد، متن صریح این الزام پیدا نشد.)

## ۴. آیکون اپ iOS

منابع: [AppLaunchFlow — iOS 26 icon sizes](https://www.applaunchflow.com/blog/ios-26-app-icon-sizes-variants) و [Create with Swift — Icon Composer](https://www.createwithswift.com/crafting-liquid-glass-app-icons-with-icon-composer/). صفحه‌ی رسمی Apple HIG از این محیط قابل دسترسی نبود؛ قبل از خروجی نهایی با [Apple HIG — App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons) تطبیق بده. ⚠️

| مورد | مقدار |
|---|---|
| ابعاد طراحی | ۱۰۲۴×۱۰۲۴ پیکسل، PNG، بدون شفافیت |
| گوشه‌ها | گوشه‌ی گرد نکش؛ سیستم ماسک رو اعمال می‌کنه |
| ساختار (iOS 26) | لایه‌ای در Icon Composer: پیش‌زمینه و پس‌زمینه جدا، حداکثر ۴ گروه عمق |
| حالت‌های نمایش (iOS 26) | ۶ حالت: پیش‌فرض، تیره، شفاف روشن، شفاف تیره، رنگی روشن، رنگی تیره |

**یعنی:** نماد باید جدا از پس‌زمینه‌ش قابل استفاده باشه و سیلوئتش در همه‌ی حالت‌ها یکی بمونه.

## ۶. تست قبل از تحویل

- [ ] نماد در ۲۹ پیکسل (کوچک‌ترین آیکون iOS در تنظیمات) هنوز قابل تشخیصه
- [ ] نماد در ماسک دایره، مربع گرد و Squircle بریده نمی‌شه
- [ ] نسخه‌ی تک‌رنگ بدون رنگ هم معنی داره
- [ ] سیلوئت نوتیفیکیشن در ۲۴ dp خواناست
- [ ] نوشتار فارسی و انگلیسی کنار نماد هم‌وزن به نظر می‌رسن
- [ ] روی پس‌زمینه‌ی روشن و تیره هر دو درست دیده می‌شه
- [ ] در کنار آیکون‌های رقبا در صفحه‌ی اصلی گوشی متمایزه

